# Email templates

Every email the agent sends comes from a fixed template. Code fills the placeholders, and
the LLM never writes outgoing text. When each email is sent is covered in
[approval.md](approval.md) and [classify-tree.md](classify-tree.md).

## Decisions

| Topic | Decision |
| --- | --- |
| Text | Fixed. Code fills `{placeholder}` values and changes nothing else. |
| Missing value | A placeholder without a value fails the render, before `SENDING` is saved. Nothing half-filled goes out. |
| Format | Plain text. No HTML. |
| Disclaimer | Every body ends with the signature delimiter `-- ` and the line `Generated by an LLM.` |
| Headers | `Subject: Re: {original_subject}`, `In-Reply-To` and `References` set to the sender's latest `Message-ID`, and the API `threadId` set to T. The same rule as [approval.md](approval.md#the-approval-request). |
| Times | Everyone shares one time zone, so times carry no zone. |
| Sender's privacy | Emails to the sender never quote the manager and never name what's in the calendar. |
| Sends | Every send uses the `SENDING` / `SENT` pattern from [retrieve-classify.md](retrieve-classify.md#sending-without-duplicates). |

## Running example

Jane (jane@acme.com) writes "Can we meet Thursday at 2pm?" with the subject
`Quick sync`. Every message stays in thread T.

## Placeholders

| Placeholder | Holds | Example |
| --- | --- | --- |
| `{original_subject}` | The first email's subject, without `Re:` | `Quick sync` |
| `{sender_name}` | The display name from `From`, or the address when there's none | `Jane` |
| `{sender_email}` | The address from `From` | `jane@acme.com` |
| `{quoted_text}` | The sender's text, each line prefixed with `> `, cut at 1000 characters | `> Can we meet Thursday at 2pm?` |
| `{slot}` | One time | `Thu 26 Nov 14:00–14:30` |
| `{slots}` | Several times, one per line, each starting with `- ` | `- Fri 27 Nov 10:00–10:30` |
| `{evidence}` | The quote a validator already checked against the email | `due today` |
| `{result}` | What the action did | `event created for Thu 26 Nov 14:00–14:30` |
| `{answers}` | The answers the pending action allows | `APPROVE, REJECT or other times` |

## Templates

| Template | To | Sent when |
| --- | --- | --- |
| [Sales decline](#sales-decline) | Sender | `SALES_OUTREACH` |
| [Approval: meeting](#approval-meeting) | Manager | A proposed time is free |
| [Approval: offer slots](#approval-offer-slots) | Manager | A meeting request has no times |
| [Approval: task](#approval-task) | Manager | A `TASK` that isn't urgent |
| [Approval: urgent task](#approval-urgent-task) | Manager | An urgent `TASK` |
| [Done](#done) | Manager | The action ran after `APPROVE` |
| [Discarded](#discarded) | Manager | `REJECT` |
| [Answer again](#answer-again) | Manager | `UNCLEAR` |
| [Urgent task notice](#urgent-task-notice) | Manager | An urgent `TASK` was approved |
| [New times](#new-times) | Sender | The manager sent `NEW_TIMES` |
| [Offered slots](#offered-slots) | Sender | Offering slots was approved |
| [Ask for other times](#ask-for-other-times) | Sender | Every time is busy, or `NO_TIMES` |
| [Approved time now busy](#approved-time-now-busy) | Manager | The second calendar check fails |
| [Decline acknowledgement](#decline-acknowledgement) | Sender | The sender `DECLINED` |
| [Sender declined](#sender-declined) | Manager | The sender `DECLINED` |
| Automatic reply | Sender | Not designed yet |

### Sales decline

```text
Hi {sender_name},

Thanks for reaching out. We're not looking for this right now, so we'll pass.

Best regards

-- 
Generated by an LLM.
```

### Approval: meeting

```text
{sender_name} <{sender_email}> asked for a meeting:

{quoted_text}

Proposed action: create an event {slot} with {sender_email}.

Reply APPROVE to book it, REJECT to discard it, or suggest other times.

-- 
Generated by an LLM.
```

### Approval: offer slots

```text
{sender_name} <{sender_email}> asked for a meeting but proposed no times:

{quoted_text}

Proposed action: offer these free slots to {sender_email}:
{slots}

Reply APPROVE to send them, REJECT to discard the request, or suggest other times.

-- 
Generated by an LLM.
```

### Approval: task

```text
{sender_name} <{sender_email}> sent a task:

{quoted_text}

Proposed action: flag the email and notify you.

Reply APPROVE or REJECT.

-- 
Generated by an LLM.
```

### Approval: urgent task

```text
{sender_name} <{sender_email}> sent an urgent task:

{quoted_text}

Why it's urgent: "{evidence}"

Proposed action: flag the email and notify you.

Reply APPROVE or REJECT.

-- 
Generated by an LLM.
```

### Done

```text
Done: {result}.

-- 
Generated by an LLM.
```

| Action | `{result}` |
| --- | --- |
| Meeting | `event created for Thu 26 Nov 14:00–14:30` |
| Offer slots | `slots sent to jane@acme.com` |
| Urgent task | `email flagged` |

### Discarded

```text
Discarded. No action was taken on {sender_name}'s email.

-- 
Generated by an LLM.
```

### Answer again

```text
I couldn't tell what you want me to do. Please reply {answers}.

-- 
Generated by an LLM.
```

| Pending action | `{answers}` |
| --- | --- |
| Meeting or offer slots | `APPROVE, REJECT or other times` |
| Task or urgent task | `APPROVE or REJECT` |

### Urgent task notice

```text
Urgent task from {sender_name} <{sender_email}>. It's flagged in the inbox.

Deadline or escalation: "{evidence}"

{quoted_text}

-- 
Generated by an LLM.
```
